    Gossil development

    Gossil is planned as a Rust library and application for versioned agentic project state. It combines Fossil version control with Gest task management. Fossil is a distributed version-control system. Gest tracks issues and tasks. Planned records include tasks, shared issues and private agent traces. Git remains the source-code authority in the first release.

    This checkout contains a bounded Fossil delta encoder and decoder, their gossil vcs diagnostics and a runner for inherited Fossil Tcl tests. It also composes byte primitives, legacy artifact checksums, token byte escaping and owned local libSQL transactions. It includes bounded structural artifact parsing, complete empty-root initialization and bounded private content storage. File-containing check-ins, Gest integration and the remaining Fossil mechanisms remain planned work.

    • Delta encoder explains creation, round-trip diagnostics and the finite compatibility evidence.
    • Delta decoder explains the library, diagnostic command, preserved fixtures and compatibility limits.
    • Inherited-test runner explains prerequisites, configuration, evidence and acceptance limits.
    • Byte digests and packed blobs describes SHA1DC safe hashes, thirteen SHA3 widths, decoding limits and native interoperability.
    • Artifact byte checksums explains bounded MD5 bytes, owned incremental computations and finite reference checks.
    • Token byte escaping describes bounded byte and C-string behavior, fallible allocation and the finite native observations.
    • Artifact parser describes the eight structural types, explicit resource limits and selected-provider date tests.
    • Local storage describes database lifecycle, exclusive transactions and the private fixture that composes storage with byte primitives.
    • Native local storage describes empty-root admission, local owner authority, finite content budgets and rollback.
    • libSQL source import boundary records exact upstream classifications and the controls required before importing the provider.
    • Native date provider describes the pinned source, integrity checks and limits of the private date regression.
    • Development plan gives the delivery order, ownership and local checkpoint workflow.
