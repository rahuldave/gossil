Gossil

Gossil aims to keep agent work, issues and file history together alongside Git. Fossil is a version-control system. This build exposes a Rust library for Fossil’s delta bytes, artifact parsing and local storage. The gossil command creates, applies and checks deltas between files without a version-control checkout. It also initializes an empty repository through vcs init, without creating a checkout. The source vcs open command registers or reopens one native checkout and publishes its lookup locator without selecting files.

The CLI and library also select explicit path scopes and record a complete private tracked tree while the shared root stays empty. Scope assigns a tracked path to shared or owner-local private history. Shared recording remains planned.

Start with a file round trip, browse the CLI reference, or use the Rust API reference. Use working with repositories to plan agent files alongside Git. It explains checkouts, stored history and the intended private and shared workflows.

For an already installed development preview, try the disposable file-history walkthrough. The preview is unmerged.

Read compare Gossil with Git for the planned coordination of file history, exact issue state and versioned links to code. The examples show library calls for deltas, compressed bytes, hashes and token escaping.

Gest is a task and artifact tracker. The converters in the module table use its record model for tasks, projects, authors, artifacts, iterations, tags, notes, relationships, entity tags and iteration tasks.

Use vcs info to show the current recorded checkout and its shared and private heads. Explicit repository and checkout selections and a complete locator are required. The source vcs timeline and vcs log commands print complete recorded ancestry as compact NDJSON. Historical revision selection remains unsupported. The library can read complete recorded ancestry through recorded_timeline, with native metadata bytes and the shared root last.

Tracking and private recording

The source add and status commands enroll exact paths and list pending or recorded paths with their stored scope. Add alone chooses neither shared nor private scope and stores no file bytes.

The private recording library requires explicit private scope for every tracked path and captures all current bytes and executable modes. The source scope and commit commands require explicit repository, checkout, scope and recording metadata. Try the private recording walkthrough. Development status separates this source contract from released and installed versions.

Glob source checkpoint

The glob module and vcs test-glob diagnostic operate without storage. The 2026-11-21 focused checkpoint passed with the selected libSQL 0.10.0 engine. It does not establish complete frozen-tree gates or release qualification. Historical 0.9.30 results remain separate. File tracking continues to use exact paths.
