storage

Own local database connections and exclusive write boundaries. Sole-connection local storage. File opens verify WAL, foreign keys, FULL and 5000 ms. Unexpected owner destruction poisons the store and closes its connection. Local SQL blocks its current poll; cancellation after COMMIT cannot undo it.

The core-only native provider has a reviewed date backport. Its source identity is recorded in evidence/libsql-provider/provenance.json. Native repository creation and admission parse the empty root on this same connection. General artifact crosslinks, runtime clocks and broader date compatibility remain unqualified. Catalog4 supports native initialization, one registration and exact private recorded history; bound catalog1 retains private writes.

Recommendations

Use one owner for a complete mutation and explicitly commit or roll back. Use LocalOwnerRepository for admitted native content and explicit finite limits.

struct LocalOwnerRepository

source

pub struct LocalOwnerRepository

A sealed local-owner handle bound to the identities read from its own database.

Opening the local file uses operating-system file permissions. A server must use a separate shared/team principal path for network requests; this handle must never be passed to a request merely because the server can open the file.

LocalOwnerRepository::recorded_timeline

source

pub async fn recorded_timeline(
    &mut self,
    checkout: &str,
    limits: AdmissionLimits,
) -> Result<Vec<RecordedCheckin>, StorageError>

Read the complete supported native ancestry of an explicitly selected checkout.

The current private check-in comes first and the immutable shared empty root comes last. Before the first private recording, that root is the sole result. Pending paths, dirty/deleted working files and filesystem contents do not affect recorded history. This performs no durable mutation and publishes no locator. A single content and parser ledger covers freshness, full admission, metadata ownership and result retention in one transaction.

Errors

Refuses missing/foreign checkout, stale authority, unsupported or corrupt state, invalid/exhausted limits, allocation/provider and checked cleanup errors. Existing operation causes and separate cleanup failures are preserved.

Examples
async fn history(owner: &mut gossil::storage::LocalOwnerRepository, limits: gossil::storage::AdmissionLimits) {
    let rows = owner.recorded_timeline("work", limits).await.unwrap();
    assert!(!rows.last().unwrap().private);
}
Parameter Type Description
checkout &str Existing nonempty NUL-free registration ID, at most 1024 bytes and parser input bytes.
limits AdmissionLimits Explicit finite cumulative content, metadata and parser ceilings.
returns Result<Vec<RecordedCheckin>, StorageError> Complete authenticated current-first ancestry including the shared root, only after checked transaction completion; never a truncated or empty history.

LocalStore::open

pub async fn open(path: impl AsRef<Path>) -> Result<Self, StorageError>

Open and verify a local file database; never fall back to memory. Nonempty paths are literal native filenames, including file: and URI punctuation. Raw Unix filename bytes remain subject to the filesystem’s acceptance rules.

Errors

Returns an error for invalid input, open, configuration or verification failure. An embedded NUL returns an error with a std::ffi::NulError source. Driver failures retain their original libsql::Error source.

Examples
use gossil::storage::LocalStore;
let mut store = LocalStore::open(path).await?;
assert!(!store.is_poisoned());
store.begin_write().await?.commit().await?;
store.begin_write().await?.rollback().await?;
Parameter Type Description
path impl AsRef<Path> Local database file, whose parent must exist.
returns Result<Self, StorageError> A store with one verified idle connection.

WriteTransaction::commit_checked

source

pub async fn commit_checked(self) -> Result<(), CommitFailure>

Commit all changes while preserving independent operation and cleanup causes.

Errors

Returns CommitFailure::operation for the original latched, COMMIT or idle-restoration error. CommitFailure::cleanup retains any independent rollback or idle-restoration error. An uncertain connection is discarded and the store poisoned.

Examples
use gossil::storage::{CommitFailure, LocalStore, StorageError};

async fn finish(store: &mut LocalStore) -> Result<(), StorageError> {
    let transaction = store.begin_write().await?;
    match transaction.commit_checked().await {
        Ok(()) => Ok(()),
        Err(CommitFailure { operation, cleanup }) => {
            if let Some(cleanup) = cleanup {
                eprintln!("cleanup failed: {cleanup}");
            }
            Err(operation)
        }
    }
}
Parameter Type Description
returns Result<(), CommitFailure> The commit succeeds only after COMMIT and confirmed idle restoration.
